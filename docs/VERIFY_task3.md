# Как проверить задачу 3 (поддержка пользователей)

Задача 3 из `docs/Final_task.md`: мини-сервис поддержки отвечает на вопросы о
продукте, использует RAG по FAQ и учитывает контекст пользователя/тикета;
тикеты и CRM-данные подключены через MCP.

Все команды выполняются из корня проекта (`G:\9potok\1610`).

## 1. Автономные тесты (без сети, MCP и Ollama)

```powershell
python -m tests.check_support
```

Ожидаемо: `Итог: 106 OK, 0 FAIL`. Проверяются JSON-данные, поиск пользователей
и тикетов, форматирование контекста, `resolve_context`, инструменты
`support_server`, индексатор FAQ, изоляция RAG по `docs/support`, разбор
`/support`, MCP → fallback JSON, передача контекста агенту и полный путь
`/support` через HTTP-обработчик.

## 2. Индексация FAQ

Нужна запущенная Ollama с моделью `nomic-embed-text-v2-moe` (`ollama list`).

```powershell
python support_index.py
```

Ожидаемо: `[support] индекс: files=2 chunks>0 errors=[]` и каталог
`G:\9potok\1610\docs\support`. Индекс общий (`session/rag_index.db`), но поиск
`/support` ограничен только `docs/support`.

## 3. Чат

```powershell
python rtk_web.py 8123
```

Откройте `http://127.0.0.1:8123/`, выберите модель (или запустите локальную) и
отправьте:

```text
/support T-1001 Почему не работает авторизация?
/support ticket=T-1001 --no-rag что проверить?
/support user=anna@example.com какие мои обращения?
/support Как сбросить пароль?
```

Что проверить в ответе:

- четыре раздела: `## Краткий ответ`, `## Почему так`, `## Что сделать`,
  `## Когда эскалировать`;
- упоминание ошибки `401`, смены пароля, старой вкладки и 2FA из `T-1001`;
- шаги из FAQ (выйти везде, очистить cookies, закрыть старые вкладки, войти
  заново) и условие эскалации (> 15 минут);
- блок «Источники» со ссылкой на `FAQ.md`/`product.md` (если FAQ
  проиндексирован);
- в ответе API есть `support: true`, `ticket_id: "T-1001"`,
  `support_source: "mcp"` (или `"json"`, если MCP недоступен), `rag_used`.

`/support user=...` берёт последний **открытый** тикет пользователя; если
открытых нет — последний любой. `/support Как ...` без тикета отвечает как
общая справка по продукту.

Ошибки:

- неизвестный тикет (`/support T-9999 ...`) → карточка
  «Не удалось получить данные обращения: тикет 'T-9999' не найден»;
- без выбранной модели и без запущенной локальной команда попросит выбрать
  модель (как обычный чат).

## 4. MCP-сервер отдельно

```powershell
python -c "from rtk_app import mcp_client; print(mcp_client.mcp_status(server_id='support'))"
python -c "from rtk_app import mcp_client; print(mcp_client.mcp_call_tool('get_support_context', {'ticket_id': 'T-1001'}, server_id='support'))"
```

Ожидаемо: статус `ok=True`, инструменты `ping`, `find_user`, `get_ticket`,
`list_tickets`, `get_support_context`, `stats`; вызов возвращает JSON с
`ok=true`, карточками `ticket`/`user`, готовым `text` и `rag_query`.

Инструменты только читают `support_data/users.json` и `support_data/tickets.json`.
Для реальных данных задайте `SUPPORT_DATA_DIR` на папку **вне** репозитория
(или переменную окружения) — формат тот же.

## 5. Проверка RAG-изоляции

В тесте §6 создаётся временный индекс с двумя одинаковыми фрагментами:
`docs/support/FAQ.md` и `docs/other/notes.md`. Поиск с
`docs_dir=docs/support` возвращает только FAQ. Это защищает ответы поддержки от
подмешивания кода и документации других проектов, которые тоже лежат в общем
индексе.

## 6. Что считать успехом

- `check_support` — 0 FAIL;
- `/support T-1001 ...` отвечает по данным тикета и FAQ, а не общими словами;
- в ответе видны 401/смена пароля/2FA и шаги из FAQ;
- `/support user=...` находит пользователя и его последнее открытое обращение;
- MCP-сервер `support` отвечает, а при его недоступности `/support` продолжает
  работать через JSON (fallback);
- ссылки «Источники» открывают `FAQ.md`/`product.md` (fallback `/docs/` на
  каталог поддержки);
- `/docs/support_data/users.json` возвращает **403** — данные обращений не
  отдаются через статический маршрут.

## Типовые проблемы

| Симптом | Причина / решение |
|---|---|
| `Не выбрана ни одна модель` | выберите модель в селекторе или запустите локальную |
| `тикет ... не найден` | проверьте ID (`T-1001`) и `SUPPORT_DATA_DIR` |
| нет блока «Источники» | выполните `python support_index.py` при запущенной Ollama |
| `RAG по FAQ ... фрагментов=0` | FAQ не проиндексирован или порог `RAG_MIN_SCORE` слишком высок |
| MCP-вызов долгий/не отвечает | сервер запускается как подпроцесс; проверьте `python -c "import mcp"` и `MCP_TIMEOUT` |
| ответ не учитывает старую вкладку | убедитесь, что тикет `T-1001` и история обращения попали в контекст (`support_context`) |
